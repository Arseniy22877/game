# API: фронт ↔ бэк

Контракт между `web/` и сервером. Go-структуры с теми же именами лежат в `internal/api/dto.go`.
Меняется только отдельным PR с согласия бэка и фронта (см. AGENTS.md).

## Общее

- Базовый путь REST: `/api`. Тела запросов и ответов в JSON, `Content-Type: application/json`.
- Имена полей в `camelCase`. Массивы всегда приходят массивами (`[]`, а не `null`). Отсутствующий объект приходит как `null`.
- Номера раундов начинаются с 1. Вероятности и значения атрибутов — числа с плавающей точкой, деньги и QP — целые.
- Время — строки RFC 3339 в UTC (`2026-11-14T10:00:00Z`).
- Лимиты: тело запроса до 64 КБ; название команды до 40 символов; от 1 до 10 участников, имя до 60 символов; каждое поле отчёта до 4000 символов. Строки обрезаются по пробелам с краёв. Нарушение лимита — `400 bad_request`.
- В разработке фронт ходит на бэк через прокси dev-сервера (`/api`, `/ws`, `/images`), в проде всё на одном origin. CORS бэк не отдаёт.

### Авторизация

| Кто | Как получает токен | Как передаёт |
|-----|--------------------|--------------|
| Команда | в ответе `POST /api/teams` | заголовок `Authorization: Bearer <token>` |
| Преподаватель | задаётся в env `ADMIN_TOKEN`, вводится на странице препода | тот же заголовок |

Для WebSocket токен передаётся в query: `/ws?token=<token>`, потому что браузер не умеет ставить заголовки на WS. К WS можно подключиться и без токена (гость): такой клиент получает только `phase_changed`. Это нужно странице команды до регистрации.

Токен команды действует только в той игре, где команду зарегистрировали. Если препод создал новую игру или удалил команду, старый токен получает `401` и команда регистрируется заново. Фронт хранит токен в `localStorage`.

**Вход с другого устройства.** У команды может быть несколько устройств одновременно, все с одним токеном. Препод видит токен каждой команды в `AdminState` и может показать ссылку для входа вида `/?token=<token>` (точный путь выбирает фронт). Страница команды, получив `token` в адресе, кладёт его в `localStorage` и убирает из адреса. Так же команда возвращается в игру, если потеряла токен (сменила телефон, открыла инкогнито).

### Ошибки

Любой ответ с кодом 4xx/5xx:

```json
{ "error": { "code": "insufficient_money", "message": "Не хватает денег: нужно 120, есть 100" } }
```

`message` можно показывать пользователю. Логику строим только на `code`.

| HTTP | code | Когда |
|------|------|-------|
| 400 | `bad_request` | невалидный JSON, нет обязательного поля |
| 401 | `unauthorized` | нет токена, токен неверный или от прошлой игры |
| 404 | `not_found` | нет такой команды, игры, сценария |
| 409 | `wrong_phase` | действие недоступно в текущей фазе (например, решение после закрытия раунда) |
| 409 | `no_game` | активной игры нет |
| 409 | `name_taken` | команда с таким названием уже есть (сравнение без учёта регистра и пробелов по краям) |
| 409 | `teams_not_ready` | препод начинает игру, а команд нет или не все готовы |
| 409 | `game_in_progress` | препод создаёт новую игру поверх идущей без `confirm: true` |
| 409 | `team_bankrupt` | у команды не хватает денег на раунд, в этом раунде она решение не отправляет |
| 409 | `not_all_submitted` | препод закрывает раунд, а не все команды отправили решение |
| 409 | `not_all_teams` | в выборе событий указаны не все команды |
| 422 | `invalid_decision` | движок отклонил решение (неизвестный id, закрытая стратегия, значение вне диапазона) |
| 422 | `insufficient_money` | не хватает денег на решение |
| 422 | `insufficient_qp` | не хватает QP на исследования |
| 422 | `invalid_event` | выбрано событие, которого нет в прогнозе команды, или одно событие указано дважды |
| 500 | `internal` | ошибка сервера |

## Фазы игры

В каждый момент на сервере не больше одной активной игры.

```
none ──create──▶ lobby ──start──▶ round_open ──close──▶ round_closed ──events──▶ round_open (round+1)
                                       │                      │
                                       └──finish──▶ finished ◀┘ events с finish: true
```

| Фаза | Что происходит |
|------|----------------|
| `none` | активной игры нет, ждём, пока препод её создаст |
| `lobby` | команды регистрируются и жмут «Готовы» |
| `round_open` | команды отправляют решения (можно переотправлять до закрытия раунда) |
| `round_closed` | препод видит прогнозы событий и выбирает, какие произойдут |
| `finished` | игра окончена, препод ставит оценки |

Завершить игру можно двумя способами:
- обычный: в `POST /api/admin/round/events` передать `finish: true`. События последнего раунда применяются, и игра сразу переходит в `finished`, новый раунд не открывается;
- запасной: `POST /api/admin/game/finish` из фазы `round_open`. Решения, уже присланные в этом раунде, отбрасываются.

В фазе `finished` поле `round` равно номеру последнего полностью сыгранного раунда.

Переходы необратимы: отменить закрытие раунда или выбор событий нельзя. Фронт должен спрашивать подтверждение у препода.

## Общие объекты

### GameInfo

```json
{
  "gameId": 3,
  "phase": "round_open",
  "round": 2,
  "scenarioId": "demo",
  "baseRoundCost": 5
}
```

В фазе `none` поле `gameId` равно `0`, `scenarioId` — пустой строке. До старта `round` = `0`, а `scenarioId` может быть пустым.
`baseRoundCost` — фиксированная плата за каждый раунд (см. «Стоимость решения»).

### TeamSummary

```json
{
  "id": 1,
  "name": "Ромашка",
  "members": ["Аня", "Петя"],
  "ready": true,
  "online": true,
  "submitted": false,
  "bankrupt": false
}
```

- `online` показывает, есть ли у команды хотя бы одно открытое WS-соединение.
- `submitted` значит, что команда сама отправила решение текущего раунда. В лобби всегда `false`. Если препод закрыл раунд с `force`, у не сдавших команд остаётся `false`.
- `bankrupt` значит, что команда пропускает текущий раунд: денег не хватает даже на самый дешёвый вариант (`baseRoundCost` плюс все слайдеры на минимуме). Проверяется при открытии каждого раунда. Такая команда решение не отправляет (`409 team_bankrupt`) и закрытию раунда не мешает; за раунд с неё ничего не списывается, её стратегии отключаются, слайдеры остаются на прежних уровнях. Прогнозы событий для неё считаются как обычно, и препод может выбрать ей событие (например, кредит). Если после событий денег хватает, со следующего раунда команда играет дальше.

### TeamGameState

Состояние экземпляра игры одной команды, как его видит команда.

```json
{
  "budget": { "money": 95, "maxMoney": 150, "qp": 8 },
  "attributes": [
    { "id": 0, "name": "Доверие", "description": "Доверие рынка", "value": 0.55, "min": 0, "max": 1 }
  ],
  "configurable": [
    { "id": 10, "name": "Маркетинг", "description": "...", "value": 0.3, "min": 0, "max": 1, "costPerUnit": 100 }
  ],
  "strategies": [
    { "id": 1, "name": "Агрессивный рост", "description": "...", "cost": 20, "active": true }
  ],
  "hints": [
    { "id": 2, "name": "Опрос клиентов", "description": "...", "reliability": "средняя", "cost": 3, "used": true, "secret": "Клиенты недовольны ценой" }
  ],
  "history": [
    {
      "round": 1,
      "events": [
        { "id": 4, "name": "Утечка данных", "description": "...", "imageUrl": "/images/leak.png", "isPositive": false }
      ]
    }
  ]
}
```

- `attributes` — ключевые (базовые) атрибуты. Команда ими напрямую не управляет. `value` — текущее значение с учётом активных стратегий.
- `configurable` — сферы бюджета, то есть слайдеры. `value` — уровень, выбранный в прошлом раунде (или значение по умолчанию). Подставляйте его как начальное положение слайдера.
- `strategies` — только открытые стратегии, закрытые не приходят. `active: true` значит, что стратегия работает с прошлого раунда.
- `hints` — исследования (в движке `Hints`), тоже только открытые. `secret` приходит непустым только при `used: true`. Исследование становится `used` и раскрывает `secret` после закрытия раунда, в котором его купили. Повторно купить использованное исследование нельзя.
- `history` — произошедшие события по раундам, от старых к новым. Раунды без событий тоже попадают в список, с пустым `events`.
- В фазе `round_closed` состояние уже учитывает решение раунда (деньги и QP списаны, исследования раскрыты), но ещё не учитывает события.
- Все списки отсортированы по `id`.

### Event

```json
{ "id": 4, "name": "Утечка данных", "description": "...", "imageUrl": "/images/leak.png", "isPositive": false }
```

`imageUrl` — готовый адрес для `<img src>`: либо путь от корня сайта (картинки сценариев бэк раздаёт по `/images/...`), либо полный `http(s)`-адрес, либо пустая строка, если картинки нет.

### Decision

Решение команды за раунд.

```json
{
  "attributes": [ { "id": 10, "value": 0.4 } ],
  "strategies": [1],
  "hints": [2],
  "report": {
    "why": "Почему именно такое решение",
    "alternative": "Какое могло быть другое",
    "risks": "Какие риски с ним связаны",
    "correction": "Что изменили бы, если бы это была не игра, а реальная жизнь"
  }
}
```

- `attributes` должен содержать **каждый** настраиваемый атрибут ровно один раз. `value` — абсолютный уровень от `min` до `max`, а не сдвиг.
- `strategies` — полный набор стратегий на этот раунд. Активная стратегия, которую не выбрали снова, отключается. Стратегия оплачивается в каждом раунде, где она выбрана.
- `hints` — исследования, которые покупаем в этом раунде. Только из списка `hints` с `used: false`.
- В `attributes`, `strategies`, `hints` не должно быть повторов и id, которых нет в `TeamGameState`. Иначе `422 invalid_decision`.
- Все четыре поля `report` обязательны (могут быть пустой строкой, но фронт должен просить их заполнить).

#### Стоимость решения

Бэк проверяет стоимость при отправке. Фронт может посчитать её сам, чтобы показывать заранее:

```
money = baseRoundCost + Σ round(value × costPerUnit) по configurable + Σ cost выбранных стратегий
qp    = Σ cost выбранных исследований
```

Ограничения: `money ≤ budget.money`, `qp ≤ budget.qp`. Деньги и QP списываются, когда препод закрывает раунд.
`round` — это `Math.round` в JS (в Go `math.Round`), округляется каждое слагаемое отдельно.

### Prediction

Возможное событие для команды с вероятностью. Видит только препод.

```json
{ "event": { "id": 4, "name": "Утечка данных", "description": "...", "imageUrl": "/images/leak.png", "isPositive": false }, "probability": 0.37, "suggested": true }
```

- `probability` — от 0 до 1, у каждого события своя, в сумме они не дают 1.
- `suggested` — подсказка для препода: бэк один раз при закрытии раунда разыгрывает события по правилам движка (с учётом вероятностей и лимита событий за раунд) и помечает выпавшие. Фронт может заранее отметить их галочками. Выбор всё равно делает препод, и бэк применяет только то, что пришло в `POST /api/admin/round/events`.

## REST: публичное

### `GET /api/game`

Без авторизации. Нужен странице команды, чтобы понять, что показывать.
Ответ `200`: `GameInfo`.

## REST: команда

### `POST /api/teams`

Регистрация команды (кнопка «Готовы» на странице команды). Доступно только в фазе `lobby`. Зарегистрированная команда сразу считается готовой.

Запрос:
```json
{ "name": "Ромашка", "members": ["Аня", "Петя"] }
```
Ответ `201`:
```json
{ "token": "b3f1…", "team": { /* TeamSummary */ } }
```
Ошибки: `wrong_phase`, `no_game`, `name_taken`, `bad_request` (пустое название или нет участников).

### `PUT /api/team/ready`

Снять или вернуть готовность в лобби. Только фаза `lobby`.

Запрос: `{ "ready": false }`. Ответ `200`: `TeamSummary`.

### `GET /api/team/state`

Полное состояние для команды. Фронт вызывает его при загрузке, после переподключения WS и при получении `phase_changed` / `team_state`.

Ответ `200`:
```json
{
  "game": { /* GameInfo */ },
  "team": { /* TeamSummary */ },
  "opening": { /* Event */ },
  "state": { /* TeamGameState */ },
  "decision": { /* Decision */ }
}
```

- `opening` — вступительное событие сценария (правила и сеттинг). Его показывают при старте игры. В лобби приходит `null`.
- `state` в лобби приходит `null`.
- `decision` — уже отправленное решение текущего раунда (чтобы заполнить форму), иначе `null`. В `round_closed` это решение, с которым раунд закрыт. В `finished` всегда `null`.

### `POST /api/team/decision`

Отправить или переотправить решение. Только фаза `round_open`. Новое решение заменяет старое.

Запрос: `{ "round": 2, ...Decision }`, то есть объект `Decision` с дополнительным полем `round`. Если `round` не совпадает с текущим раундом, ответ будет `409 wrong_phase` (защита от устаревшей вкладки).

Ответ `200`:
```json
{ "cost": { "money": 75, "qp": 3 } }
```
Ошибки: `wrong_phase`, `team_bankrupt`, `invalid_decision`, `insufficient_money`, `insufficient_qp`, `bad_request`.

Если решение отклонено, прежнее отправленное решение остаётся в силе.

## REST: преподаватель

Все эндпоинты требуют `ADMIN_TOKEN`.

### `GET /api/admin/scenarios`

Ответ `200`: `{ "scenarios": [ { "id": "demo" } ] }`. `id` равен имени файла в `scenarios/` без `.json`, это значение для селекта сценария.

### `POST /api/admin/game`

Создать новую игру в фазе `lobby`. Если активная игра уже есть, она архивируется (остаётся в истории), а токены её команд перестают действовать.

Запрос: `{ "confirm": false }` (тело можно не слать). Если активная игра сейчас в фазе `round_open` или `round_closed`, без `confirm: true` придёт `409 game_in_progress`: это защита от случайного нажатия посреди занятия.

Ответ `201`: `AdminState`.

### `DELETE /api/admin/teams/{teamId}`

Удалить команду. Только фаза `lobby`. Нужно, чтобы убрать дубль или команду, которая не даёт начать игру. Токен команды перестаёт действовать, её WS-соединения закрываются.

Ответ `200`: `AdminState`. Ошибки: `wrong_phase`, `not_found`.

### `GET /api/admin/state`

Полное состояние для препода.

Ответ `200` (`AdminState`):
```json
{
  "game": { /* GameInfo */ },
  "teams": [
    {
      "id": 1, "name": "Ромашка", "members": ["Аня"], "ready": true, "online": true, "submitted": true, "bankrupt": false,
      "token": "b3f1…",
      "state": { /* TeamGameState */ },
      "decision": { /* Decision */ },
      "cost": { "money": 75, "qp": 3 },
      "predictions": [ /* Prediction */ ]
    }
  ]
}
```

Команды отсортированы по `id` (в порядке регистрации). Поля команды — это `TeamSummary` плюс:
- `token` — токен команды, для ссылки входа с другого устройства;
- `state` — `null` в лобби;
- `decision` и `cost` — решение текущего раунда, `null`, пока не отправлено, и всегда `null` у команды с `bankrupt: true`. После закрытия раунда с `force` у не сдавших команд здесь решение по умолчанию (при этом `submitted: false`). В фазе `finished` оба `null`;
- `predictions` — непустой только в фазе `round_closed`, отсортирован по убыванию вероятности.

### `POST /api/admin/game/start`

Начать игру выбранным сценарием. Только фаза `lobby`, нужна хотя бы одна команда, все команды должны быть `ready`.

Запрос: `{ "scenarioId": "demo" }`. Ответ `200`: `AdminState` (фаза `round_open`, раунд 1).
Ошибки: `wrong_phase`, `not_found` (нет сценария), `teams_not_ready` (нет команд или не все готовы).

### `POST /api/admin/round/close`

Завершить раунд. Только фаза `round_open`. Бэк применяет решения (`CalculateState`) и считает прогнозы (`GetPredicts`).

Запрос: `{ "round": 2, "force": false }`. `round` — номер раунда, который препод закрывает; если он не совпадает с текущим, придёт `409 wrong_phase` (защита от устаревшей вкладки и двойного нажатия).

Без `force` все команды (кроме тех, у кого `bankrupt: true`) должны отправить решение, иначе ответ `409 not_all_submitted`. С `force: true` команды без решения получают решение по умолчанию: слайдеры остаются на уровнях прошлого раунда и оплачиваются как обычно, стратегий и исследований нет, отчёт пустой. Если на прежние уровни не хватает денег, все слайдеры ставятся на минимум.

Ответ `200`: `AdminState` (фаза `round_closed`, у команд заполнены `predictions`).

### `POST /api/admin/round/events`

Применить выбранные события и открыть следующий раунд. Только фаза `round_closed`.

Запрос: в нём должна быть каждая команда игры ровно один раз, включая команды с `bankrupt: true`. Пустой `eventIds` значит, что событий не будет. События применяются в том порядке, в котором перечислены.
```json
{ "round": 2, "finish": false, "selections": [ { "teamId": 1, "eventIds": [4] }, { "teamId": 2, "eventIds": [] } ] }
```
- `round` — номер раунда, для которого выбраны события. Не совпал с текущим — `409 wrong_phase`.
- `finish: true` — это был последний раунд: события применяются, игра переходит в `finished`.

Ответ `200`: `AdminState` (фаза `round_open` и `round` + 1, либо `finished`).
Ошибки: `wrong_phase`, `not_all_teams`, `invalid_event`, `bad_request` (команда указана дважды или её нет в игре).

### `POST /api/admin/game/finish`

Завершить игру без применения событий. Только фаза `round_open`, решения текущего раунда отбрасываются. Обычный способ завершения — `finish: true` в `POST /api/admin/round/events`.

Ответ `200`: `AdminState` (фаза `finished`).

### `GET /api/admin/games`

История игр, от новых к старым, включая текущую:

```json
{ "games": [ { "gameId": 3, "scenarioId": "demo", "phase": "finished", "rounds": 5, "active": true, "createdAt": "2026-11-14T10:00:00Z" } ] }
```

- `phase` — фаза, в которой игра сейчас или в которой её заархивировали. Архивная игра с фазой не `finished` была прервана.
- `rounds` — сколько раундов сыграно полностью.
- `active` — это текущая игра сервера.

### `GET /api/admin/games/{gameId}`

Полные данные одной игры (текущей или прошлой): по ним препод читает отчёты и ставит оценки.

```json
{
  "game": { /* элемент из GET /api/admin/games */ },
  "teams": [
    {
      "id": 1, "name": "Ромашка", "members": ["Аня"],
      "rounds": [
        {
          "round": 1,
          "decision": { /* Decision */ },
          "cost": { "money": 75, "qp": 3 },
          "auto": false,
          "predictions": [ /* Prediction */ ],
          "events": [ /* Event */ ],
          "state": { /* TeamGameState */ }
        }
      ],
      "grades": [ { "skill": "risks", "score": 8, "comment": "" } ]
    }
  ]
}
```

- `rounds` — только закрытые раунды, от первого к последнему.
- `decision` и `cost` равны `null`, если команда пропустила раунд из-за нехватки денег (`bankrupt`).
- `auto: true` — команда не сдала решение, применено решение по умолчанию.
- `events` — события, которые препод выбрал для команды в этом раунде.
- `state` — состояние команды на конец раунда (после событий). У раунда, который закрыт, но события ещё не выбраны, это состояние после решения.

Ошибки: `not_found`.

### `PUT /api/admin/games/{gameId}/teams/{teamId}/grades`

Оценки препода: одна на каждый навык команды за всю игру. Навыки фиксированы (слайд «Навыки для оценки» в ТЗ) и от сценария не зависят:

| `skill` | Навык |
|---------|-------|
| `problem_statement` | Постановка задачи |
| `fact_checking` | Проверка информации |
| `connections` | Поиск связей |
| `alternatives` | Рассмотрение альтернатив и возражений |
| `risks` | Оценка рисков |
| `revision` | Пересмотр и объяснение |

Игра должна быть завершена (`finished`) или заархивирована, то есть оценки можно ставить и после занятия, когда на сервере уже идёт другая игра. Для идущей игры — `409 wrong_phase`.

Запрос содержит полный набор оценок команды и заменяет прежний:

```json
{ "grades": [ { "skill": "risks", "score": 8, "comment": "" } ] }
```

- `skill` — код навыка из таблицы, каждый не больше одного раза. Можно прислать не все шесть.
- `score` — целое от 0 до 10.
- `comment` — до 2000 символов, может быть пустым.

Ответ `200`: тот же объект. Ошибки: `not_found`, `wrong_phase`, `bad_request`.

## WebSocket

`GET /ws?token=<token>` с токеном команды или препода, либо без токена (гость). С неверным токеном сервер отвечает `401` и соединение не открывает. Сервер только шлёт сообщения, клиент ничего не отправляет. При обрыве клиент переподключается сам (с паузой 1–5 секунд).

Формат: `{ "type": "...", "payload": { ... } }`.

После (пере)подключения клиент делает `GET /api/team/state` или `GET /api/admin/state`. WS-сообщения не дублируют полное состояние, они говорят, что изменилось. Если сообщение пропущено, ничего не ломается: следующий GET всё равно вернёт актуальные данные.

| type | Кому | payload | Когда |
|------|------|---------|-------|
| `phase_changed` | всем, включая гостей | `GameInfo` | создание игры, старт, закрытие раунда, новый раунд, конец игры |
| `lobby_updated` | преподу и командам | `{ "teams": [TeamSummary] }` | команда зарегистрировалась, сменила готовность, удалена, подключилась или отключилась (в лобби) |
| `submission_updated` | преподу и этой команде | `{ "teamId": 1, "submitted": true }` | команда отправила или переотправила решение. Другие устройства той же команды по нему перечитывают состояние |
| `team_online` | преподу | `{ "teamId": 1, "online": false }` | у команды появилось первое или закрылось последнее соединение (во время раундов) |
| `team_state` | конкретной команде | `{ "round": 3, "events": [Event] }` | события раунда `round` применены. В `events` то, что произошло с командой. Приходит перед `phase_changed`. После этого клиент делает `GET /api/team/state` |

Когда препод создаёт новую игру, сервер шлёт всем `phase_changed` и закрывает соединения команд прошлой игры. При удалении команды её соединения тоже закрываются.

Что делает клиент на `phase_changed`:
- команда: при `gameId`, отличном от сохранённого, сбрасывает токен и показывает регистрацию; в остальных случаях делает `GET /api/team/state` и переключает экран;
- препод: делает `GET /api/admin/state`.
